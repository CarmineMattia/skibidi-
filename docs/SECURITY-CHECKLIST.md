# Checklist sicurezza — 20 modi di bucare un'app vibecoded

Stato sul branch di hardening, rispetto a `main` (`ca2ad723`).
«Dashboard» è ciò che Carmine deve fare a mano su Supabase o Vercel.
Le migration `supabase/migrations/20261111234500_security_hardening.sql` e `supabase/migrations/20261112003000_company_storage_and_orders_anon.sql` **non** sono applicate al progetto `zqubwvhstobaugifzoyb`: vanno applicate solo con il suo OK.

| # | Voce | Stato | Evidenza | Resta in dashboard |
| --- | --- | --- | --- | --- |
| 1 | Header auth bypass | Mitigato nel codice | La sessione è il JWT di Supabase (`lib/api/supabase.ts`). L'app non autentica da un header tipo `X-User-Id`. | Non aggiungere endpoint che fidano un header inventato. Il segreto JWT resta in Supabase, non nel client. |
| 2 | Esposizione di `.git` | Mitigato dal deploy | `vercel.json` pubblica solo `dist` (`outputDirectory`), prodotto da `npm run build:web`. `.git` non entra nell'export. | Il progetto Vercel deve usare quel build command. Non servire la root del repo. |
| 3 | Supabase storage | Chiuso in questa PR (file) | Le migration tolgono insert/update/delete aperti a ogni utente autenticato sul bucket `products`. Scrive solo un admin, e solo sotto `{company_id}/...` (`20261112003000`). Il bucket resta pubblico: un URL noto, anche di una foto vecchia senza cartella, continua a funzionare. La SELECT di listing resta allo staff e non esige il prefisso, così le foto già caricate si vedono ancora. MIME `image/jpeg`, `image/png`, `image/webp`, tetto 5 MB. L'editor admin valida tipo e dimensione prima dell'upload e mostra l'errore (anche un 400 di Storage) nel modale. | Applicare le migration. Poi, in Storage, controllare che non restino policy di scrittura sul bucket `products` per tutti gli autenticati o senza il prefisso della company. |
| 4 | Prezzo deciso dal client | Già mitigato | `20261020150000_server_side_pricing.sql`: `create_order_with_items` ignora i prezzi del client e usa `order_line_priced`. | Niente. |
| 5 | Credential stuffing | Parziale | Login pubblico solo Google. La password admin è spenta se non si builda con `EXPO_PUBLIC_ENABLE_ADMIN_PASSWORD_LOGIN` (`lib/stores/AuthContext.tsx`). | Accendere leaked-password protection. Non alzare i rate limit di sign-in. Tenere le registrazioni email spente. Se la password di `admin@skibidi.com` resta, cambiarla: quella storica è debole. |
| 6 | Database aperto | Parziale, chiuso nei file | RLS già attiva. `20261111234500` revoca a anon/authenticated i privilegi che nessuna policy usa (`order_daily_counters` e le tabelle uguali) più TRUNCATE, TRIGGER, REFERENCES e, su PostgreSQL 17, MAINTAIN. `20261112003000` toglie a `anon` ogni privilegio su `orders` e `order_items` e mette `TO authenticated` sulle policy che erano ancora pubbliche. | Applicare le migration. Non disattivare la RLS. Non mettere la `service_role` nel client. |
| 7 | Script da CDN | Mitigato | `app/+html.tsx` non carica script di terzi (solo JSON-LD inline). Turnstile carica `challenges.cloudflare.com` solo se c'è `EXPO_PUBLIC_TURNSTILE_SITE_KEY` (`components/features/TurnstileWidget.tsx`). | Se si accende Turnstile, la verifica resta l'edge function `verify-turnstile`. La site key è pubblica per design. |
| 8 | SMS pumping | Non applicabile | Nessun provider telefono, Twilio o OTP SMS nel codice. | Non abilitare il provider Phone. Se un giorno serve, rate limit e CAPTCHA prima dell'invio. |
| 9 | Prompt injection | Chiuso per il prototipo | L'assistente ordini non è montato da nessuna schermata e non è riesportato da `lib/hooks/index.ts`. Metro lo sostituisce con `lib/dev/orderAssistantStub.ts` salvo `EXPO_PUBLIC_ENABLE_ORDER_ASSISTANT=true` in un build che non è production (`metro.config.js`). `server/order-assistant.ts` è solo `npm run chat:server`. | Non impostare quel flag sul progetto Vercel. Non pubblicare il server della chat. |
| 10 | JWT debole | Mitigato da Supabase | Il client non firma e non verifica JWT a mano. La anon key è pubblica per design; i dati li protegge la RLS. | Non disattivare la verifica JWT. Non copiare la service role nel browser. |
| 11 | Race condition | Già mitigato | `pg_advisory_xact_lock` in `create_order_with_items` e in `assert_order_antiabuse`. Il codice ordine è il contatore `order_daily_counters`, ora senza grant al client. | Applicare le migration antiabuso se non sono già su prod. Questa PR non le riesegue. |
| 12 | Account pre-hijacking | Chiuso nei file | `handle_new_user` non legge `role` né `company_id` dai metadata: ruolo `customer`, company da `default_customer_company_id`. Il nome mostrato da Google (`name`) viene copiato se manca `full_name`. `avatar_url` / `picture` vengono copiati solo se la tabella `profiles` ha una colonna avatar (oggi non c'è). Il client non manda role né company. Grant di colonna e trigger `prevent_profile_privilege_escalation`. | Email sign-up disattivato (l'admin con password resta utilizzabile). Niente automatic linking di identità non confermate. Secure email change acceso se il provider email resta acceso. Vedi `docs/AUTH-GOOGLE.md`. |
| 13 | Subdomain takeover | Fuori dal codice | L'URL di produzione documentato è `https://skibidi-eight-virid.vercel.app`. Nel repo non c'è un CNAME. | In Vercel/DNS non lasciare CNAME verso progetti cancellati. Non aggiungere domini che non controllate. |
| 14 | SSRF | Mitigato | Nessun proxy server che fetcha un URL dell'utente. Il geocoding è nel browser verso Nominatim (`lib/utils/geocoding.ts`). L'edge function Turnstile parla solo con Cloudflare. | Non aggiungere un fetch server verso URL arbitrari. |
| 15 | Path traversal | Mitigato | Il deploy è l'export statico. `scripts/serve-vercel-static.mjs` normalizza il path e resta dentro `dist` (solo verifica locale). | Vercel serve i file esportati, non path scelti dall'utente. |
| 16 | Reset poisoning | Mitigato nel client | Nessun `resetPasswordForEmail`. Il redirect OAuth è l'origine corrente + `/login`, oppure `pizzeriaambrosia://login` (`getOAuthRedirectUrl`). Non c'è un parametro `next` letto dalla query. | Allowlist esatta in Authentication → URL Configuration. Vietato `https://*.vercel.app/**`. Elenco in `docs/AUTH-GOOGLE.md`. |
| 17 | Source map | Non pubblicate dalla config | `app.json` e `vercel.json` non espongono source map. | Dopo il deploy, controllare che gli URL `*.map` sotto `/_expo/static/js/web/` non rispondano 200. |
| 18 | Clickjacking | Chiuso in questa PR | `vercel.json`, source `/(.*)`: `X-Frame-Options: DENY`, `Content-Security-Policy: frame-ancestors 'none'`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy` con `geolocation=(self)` (il pulsante «Usa posizione») e camera, microfono e payment spenti. La CSP non aggiunge `script-src`: Expo web, Supabase, Google OAuth e le immagini restano com'erano. | Il deploy Vercel deve usare questo `vercel.json`. Una CSP più stretta (`script-src`, `connect-src`) va provata a parte, non è in questa PR. |
| 19 | Open redirect | Mitigato nel client | Nessun redirect preso dalla query. L'unico `redirectTo` OAuth è quello del punto 16. | La allowlist Supabase è il controllo vero: va impostata a mano, URL per URL. |
| 20 | User enumeration | Parziale | Il form pubblico è Google. Il login password admin, se acceso, fa `signOut` quando il ruolo non è admin e mostra un messaggio generico (`signInAdminWithPassword`). | Con le registrazioni email spente non c'è il messaggio «user already registered». Tenere i rate limit. Supabase può ancora distinguere una password sbagliata: non alzare i limiti di sign-in. |
